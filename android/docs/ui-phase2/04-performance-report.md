# گزارش کارایی (معادل وب compose-performance-auditor)

UI داخل WebView است، پس قواعد اسکیل به معادل وب ترجمه شد:
- recomposition معادل رسم دوباره‌ی DOM است.
- stable key معادل `guid` ردیف است.
- `remember` / `derivedStateOf` معادل نگه داشتن گره‌ها و به‌روزرسانی فقط متن تغییرکرده است.

## اندازه‌گیری (Playwright، Chromium، ۳۹۰×۸۴۴، داده‌ی نمونه با ۷ سرور)

| سناریو | جهش‌های DOM | گره اضافه‌شده | طولانی‌ترین task |
|---|---|---|---|
| خانه، ۱۰ ثانیه در حال اتصال | ۴۷ (حدود ۴٫۷ در ثانیه: ساعت، مصرف و پینگ) | ۳۸ (فقط گره‌های متن) | ۰ ms (هیچ long task بالای ۵۰ms) |
| سرورها، «تست همه» | ۶۸ | ۲۲ | ۰ ms |
| جست‌وجوی ۷ حرف | ۱۲ (debounce ۱۵۰ms) | ۶ | ۰ ms |
| ترتیب لیست وسط تست | بدون تغییر ✓ | | |
| کل DOM صفحه‌ی سرورها | ۱۲۱ گره | | |

## یافته‌ها و اصلاح‌ها

| # | مشکل (قبل) | شدت | اصلاح |
|---|---|---|---|
| 1 | حلقه‌ی `requestAnimationFrame` کره‌ی شبکه و `setInterval` ۵۰۰ms که کل صفحه‌ی خانه را دوباره رسم می‌کرد | بالا | `netglobe.js`، `land.js` و `geo.js` حذف شدند. یک تایمر ۱ ثانیه‌ای فقط دو گره‌ی متنی را عوض می‌کند و فقط وقتی وصل هستید اجرا می‌شود. |
| 2 | هر رویداد پینگ `innerHTML` کل لیست سرور را می‌ساخت | بالا | ردیف‌های کلیددار (`Map guid→element`). رویداد `serverPing` فقط همان ردیف را رنگ می‌کند. |
| 3 | لیست وسط تست جابه‌جا می‌شد و لمس اشتباه رخ می‌داد | متوسط | ترتیب فقط بعد از پایان تست یا با عمل صریح کاربر عوض می‌شود. |
| 4 | جست‌وجو با هر کلید کل لیست را می‌ساخت | متوسط | debounce ۱۵۰ms و استفاده‌ی دوباره از گره‌های موجود. |
| 5 | به‌روزرسانی وضعیت، همه‌ی بخش‌ها را رسم می‌کرد | متوسط | رویداد `conn` با کلیدهای `phase`، `server`، `ping`، `policy`، `me`، `net` و `auto`. هر painter فقط بخش خودش را رسم می‌کند. اعلان‌ها فقط اگر HTML تغییر کرده باشد جایگزین می‌شوند. |
| 6 | تب‌ها صفحه را روی پشته جمع می‌کردند | کم | `CG.tab()` پشته را [home, tab] نگه می‌دارد و cleanup هر صفحه تایمر و listenerهایش را آزاد می‌کند. |
| 7 | فونت سیستم نادیده گرفته می‌شد (`textZoom=100`) | دسترس‌پذیری | `--fs` از `fontScale` می‌آید. صفحه‌های قدیمی پیکسلی دست نخوردند. |

## باقیمانده
- صفحه‌های قدیمی پرداخت (کارت‌به‌کارت، کریپتو، سفارش‌ها) هنوز پیکسلی هستند و با فونت بزرگ رشد نمی‌کنند. خارج از محدوده‌ی این فاز.
- با لیست خیلی بزرگ (بیش از ۲۰۰ سرور) بهتر است رندر مجازی اضافه شود. با تعداد فعلی لازم نیست.
